# A2D 评测闭环 v0

入口：[代码与运行说明](../tools/a2d_eval_loop/README.md)。

模型导出 → bundle 验收 → 既有 gRPC 评测 → 证据快照和汇总 → 下一轮任务草案 → 人工确认。

这是 L1 诊断控制层，不启动仿真或训练；每一项新增行动执行前先说明范围并取得人工确认。当前已授权任务可继续。

本实现补充 [原始 loop 方案](LOOP_FIRST_INSTANCE.md)，不把原 lifecycle 中 pending 的阶段标记成已通过。既有 gRPC runner 暂仍在部署端，尚未作为本工具的可移植执行后端发布。

验证：9 项标准库单元测试通过；本机历史 600 次尝试的六组成功/有效计数与原报告一致。新的 SSH 传输、训练提交、自动模型晋级未完成端到端验证。历史原始记录不包含在仓库中，单元测试可独立运行。

测试命令：

```bash
cd tools/a2d_eval_loop
python3 -m unittest discover -s tests -v
```

### 已有能力与实际缺口

| 工程经验 | V0 已有能力 | 下一步要补的证据 |
|---|---|---|
| 同一套考题 | bundle、plan、evaluate.py 与 loop.py 身份校验；检查计划 seed | seed 真正进入场景 reset、完整初态可复现、首帧与初态测量对齐 |
| 能追溯失败 | 不可变结果快照、三类失败摘要、invalid 单列 | 接触窗口的命令/实际状态、首次成功和首次丢失时间、终帧接触 |
| 从小到大验证 | bundle 验收和已有结果接入 | 独立模型加载 smoke、可移植 runner、受控断点恢复验收 |
| 完整结果才能比较 | task×model 尝试覆盖、描述性 Wilson 区间 | 有效样本覆盖、冻结异常上限、布局配对和晋级阈值 |

`coverage_complete` 当前表示计划尝试已齐，不表示有效样本已齐或科学资格通过。
`new-experiment` 只表示进入人工分析；代码保持 `scientifically_qualified=False`、
`ready_for_training=False`。不能把新增路线文字当作这些状态已经改变。

## 推荐执行顺序与验收门槛

| 阶段 | 具体工作 | 必须留下的证据 | 通过后做什么 |
|---|---|---|---|
| V0：固化诊断基线 | 核对现有逐轮记录、模型身份、预算和无效原因 | 每场景×模型尝试/计划、成功/有效、invalid、快照哈希 | 人工选出一个待验证问题 |
| V1a：runner 与 smoke | 包装既有 gRPC runner；检查独占控制、加载、观测、动作和结果字段 | 独立 smoke 命名空间、完整 argv、bundle/evaluator/scene 身份、单轮日志 | 只证明流程可用，不评模型优劣 |
| V1b：恢复 | 在隔离测试中验证中断、重复结果、半行写入和身份漂移处理 | 重复记录被拒绝、完整终态不重跑、未完成尝试保留、恢复前后身份一致 | 可重复运行小规模诊断 |
| V2a：考题与判据标定 | 检查 reset、完整初态、专家 replay 和真实接触/高度信号 | 同布局重复的初态偏差、首帧时间、replay 结果、成功判据核对 | 才允许声明布局配对比较 |
| V2b：小规模受控比较 | 同一任务与执行协议交替运行配置，只变一个因素 | 预先冻结的小样本预算、逐轮状态、代表性成功与失败视频 | 确认指标可用和问题可定位 |
| V2c：完整验收 | 执行预先冻结的任务×布局×模型矩阵 | 覆盖检查、异常报告、分任务结果、配对差值及不确定性 | 人工作出继续、重测或停止决定 |
| V3：训练交接 | 把诊断转成单变量假设，再接训练任务接口 | 假设、唯一改动、数据/训练预算、验收规则、人工授权 | 授权后才启动对应任务 |

样本数、reset 偏差容限、异常上限、非劣界和最低改善幅度必须在新实验前填写；本路线不
编造这些数值，也不追认已有结果达到新门槛。观察器恢复不等于仿真 runner 恢复。
既有分支文档中的 600/800 次是历史验证记录与计划，不能据此判断远端任务当前仍在运行。

## 固定考题：先验证 reset，再谈同 seed

沿用 V0 协议的新实验冻结 bundle/权重哈希、评测器版本、仿真/容器版本、物理参数、
场景与目标资产哈希、相机与预处理、动作语义、归一化、求解/采样参数、H16、300 动作、
请求频率、成功 profile、场景 seed 列表和顺序。未来 horizon 等协议消融需新的适配器版本
与独立 cycle，不能通过修改现有计划绕过 V0 的协议校验。
策略 seed 与场景 seed 分别记录；完成后报告实际频率，不能用视频 FPS 代替控制频率。

V2a 必须核查以下链路，当前未认证这些能力：

1. reset 的 seed 是否真正控制场景随机化，保存目标初始位姿/速度、机器人 qpos 和布局身份。
2. 多环境中 reset 一个环境是否推进其他环境；所有 settling 后再获取新观测和初始高度。
3. 首帧观测与初始高度是否来自同一稳定状态；重复同布局的偏差是否落在预先冻结容限内。
4. 专家 replay 校验执行链路；replay 成功不代替模型推理输入、标签与时间对齐验收。

若不具备完整初态复现，结果继续标记 diagnostic，只作分场景描述；不因 seed 数字相同就
使用配对显著性结论。配置交替运行可减轻时间漂移，不能修复 reset 不一致。

## 成功与失败：主指标保持，诊断补齐

当前主指标不变：目标相对初始高度至少 5 cm，同时满足拇指加至少另外两指接触，
连续 5 次动作后观测成立；接触力下限及比较运算以冻结的 evaluator/contract 为准。
这是“曾持续抓起”，之后掉落不取消成功。新增字段要在后续 runner 版本和新 cycle 中实现。

| 指标 | 定义与用途 |
|---|---|
| 曾持续成功（现有） | 接触和高度同时满足连续窗口；主指标 |
| 最终抬升（接收字段 `final_lift`） | V0 允许缺失；需核查部署端公式、单位和采样时刻，不能证明末帧仍抓住 |
| 最终接触且抬升（拟新增） | 同一末帧同时满足接触和高度；缺接触信号时记 unknown |
| 末尾连续保持长度（拟新增） | 从最后一帧往前连续满足的长度；不能用全程最大 streak 代替 |
| 首次成功/首次条件丢失（拟新增） | 判断成功后何时失去条件；不能仅据此断言掉落原因 |

失败分析先使用现有三类任务结果：没有有效多指接触、接触与抬升未同时满足、持续次数不足。
这些是摘要分类，尚未从物理帧独立验证；当前代码将缺失的 `contacts` 按 0 分类，遇到
缺失字段应标注证据不足，不能把该分类直接当作已证实的无接触事实。
有时序证据后再检查“手臂到位 → 手部命令 → 实际跟踪 → 接触 → 抬升 → 保持”。
参考姿态匹配只是诊断信号：先统计成功样本是否也未通过该标志，再决定能否作必要条件。
全程不同时间的最小误差不能拼成因果链；优先分析同一接触窗口的命令/实际状态及固定延迟。

## 分母、恢复和完整验收

- 保留当前尝试预算语义：100 次尝试不等于 100 个有效样本；不得悄悄补跑成功或删掉失败。
- `completed` 与 `policy_rejected` 属于有效分母；保护拒绝前的成功仍保留，同时单列拒绝比例
  和保护规则版本。不同模型的保护规则不同，是比较限制，不应通过修改保护规则掩盖。
- reset/基础设施异常分别报告。未来重试需事先冻结次数、同布局或替换规则、耗尽行为，保留
  每次 attempt；普通模型失败不重试挑最好结果。新规则只用于新 cycle。
- 报告同时展示尝试/计划、成功/有效、无效分类；可补充成功/全部尝试作为运行产出率，必须
  标明口径。不平均不同分母，也不把全无效但尝试齐全的组称为合格 benchmark。
- 恢复键需覆盖任务、布局、模型、执行协议和代码版本；只跳过身份一致且终态有效的记录。
  协议、schema、模型或判据变更必须新建 cycle，旧证据不可覆盖。
- 完整比较要求所有预定单元齐全、无重复或意外样本，并满足预先冻结的异常与有效覆盖要求。
  无证据问题但覆盖未齐时显示 `wait`；运行证据缺失/模型哈希问题优先 `retry-eval`，
  硬性身份或合约不一致会直接报错。齐全但诊断性质的报告不升级为正式排名。
- 每个场景单独给结果。只有在初态配对通过后，才对相同布局计算配对差值与区间；存在共享
  仿真/批次相关性时按批次分组处理不确定性。不能把两个 Wilson 区间是否重叠当成配对检验。

## 下一轮任务单应回答什么

1. 证据来自哪个不可变快照？最先出现差异的是任务结果还是有时序支持的诊断阶段？
2. 本轮只改什么：模型、数据、采样、执行 horizon 或控制链路中的哪一项？其余冻结什么？
3. 哪个结果支持假设，哪个结果否定假设？需要多少样本、何时停止？
4. 是补测/修复评测基础设施，还是确实需要训练？分别返回对应阶段。

最近的下一关是 **V1 runner/smoke/恢复合同与 V2a 初态标定**。先让测量可重复，
再扩大模型矩阵或接远端训练。任何新增遥测都需验证没有改变生成动作，并记录运行开销；
更改仿真端文件或实验参数依旧需要对应步骤的明确授权。
